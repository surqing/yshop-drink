# Phase 6C 公共兑换码安全补充

范围：PR #12 的兑换码防猜测 review-fix。无数据库 migration；不修改已发行权益、订单、支付、余额、积分、账本或旧兑换码。不开始 Phase 6D。

## 新码：由服务端产生，不接受人为弱码

新 CODE 活动使用 `POST /admin-api/coupon/create-code`，沿用 `coupon::create` 角色权限及完整门店资源授权。服务端 `SecureRandom` 生成24随机字节，Base64URL编码为32字符，熵来源是192个随机位，而不是字符长度或复杂度检查。手工输入的4位码或32位重复字符均被拒绝；旧 `/create` 不再创建 CODE 活动。

创建事务只保存 SHA-256 摘要；只有事务成功后的授权创建响应返回 `id`、`exchangeCode`，设置 `Cache-Control: no-store`。后台显示一次性复制窗口，关闭即清除组件内存值，不写浏览器持久化存储。列表、详情、App、券实例及操作审计不返回原码或摘要。响应审计通过既有 SensitiveDataSanitizer 删除 exchangeCode/redemptionCodeHash；DTO/创建结果 toString 也排除原码。

生产后台与App入口应使用HTTPS；反向代理不得记录兑换请求body或生成码响应body。应用脱敏不能代替代理、APM或浏览器扩展的日志配置。

本轮不提供修改或恢复原码入口。模板编辑保留已有摘要/历史原码，不隐式重置。若创建成功但响应丢失，不能从摘要恢复原码；管理员应明确停用该活动、另建随机码活动，不能删领券记录或重置权益来恢复。

## 稳定的跨实例 admission

`AppCouponController.receive` 在查券/进入领取事务前，对带 code（包括空串、错误code与id组合）或无id的兑换请求调用 CouponCodeGuard。调用方会员ID来自已认证服务端上下文，不能由请求体指定。

合理扩展现有 RateLimiterRedisDAO：新增 Redis Lua 原子固定窗口操作，复用已配置的 Redisson/Redis；不复用包含参数的 UserRateLimiterKeyResolver，不创建新的限流框架。计数值封顶，首次请求设置TTL，被拒绝的请求不延长TTL。依赖共享 Redis 而不是 JVM/Redis锁；多实例必须共用同一 Redis keyspace 并统一部署。

| 维度 | 默认额度 | key组成 |
|---|---|---|
| 已认证会员 | 5次/60秒、20次/3600秒 | 固定业务前缀 + SHA-256(uid) + 窗口 |
| 可信连接IP | 100次/60秒、1000次/3600秒 | 固定业务前缀 + SHA-256(peer address) + 窗口 |
| 历史短码输入额外保护 | 每会员3次/86400秒、每IP30次/86400秒 | 同一身份 + 固定 legacy-day 后缀 |

所有窗口从首次计数开始，不是自然整点/自然日。会员拒绝后不继续消耗共享IP额度，避免一个已被限流的会员无限耗尽同一网络额度。IP额度较宽，可支持普通共享网络；仍可能出现共享网络额度耗尽，此时明确提示稍后重试，不能绕过限流。哈希只是避免明文键，不宣称对小空间会员ID具有匿名化能力。

key不含 code、requestKey、活动ID或整个请求；改变兑换码、requestKey、目标活动都不能刷新会员额度。成功、错误、不满足资格的请求均需先消耗准入额度；达到额度后的请求直接拒绝，不进入查券事务。普通 PUBLIC 按ID领取保持原逻辑。

## 代理、重试与故障

IP仅使用 servlet `getRemoteAddr()`，应用不读取任意 X-Forwarded-For/Forwarded。生产反向代理必须限制后端直接访问、覆盖客户端伪造转发头，并通过仅信任明确代理地址的容器 RemoteIpValve 等受控机制恢复真实来源。未配置时按代理地址聚合，可能更保守，但会员维度始终有效；禁止为缓解共享网络限流而关闭会员或IP维度。

正常网络失败重试保留原 requestKey，继续走原数据库幂等记录，只返回原已领取权益；重试也消耗额度，不给猜测者免费重试通道。短码允许首次加两次重试，耗尽后等待固定窗口恢复。前端保留动作key，不将限流解释为成功。

Redis超时、不可用或脚本异常统一 fail closed：503“兑换服务暂时不可用，请稍后重试”，不查券、不写领取数据，无本地放行或无锁降级。额度拒绝返回429“兑换尝试过于频繁，请稍后重试”。状态沿用本项目 CommonResult 业务code约定，不声称已更改全局 HTTP status 契约。

限流组件不记录code、完整请求、会员/IP、Redis异常消息或异常cause。既有 RateLimiterAspect 的拒绝日志也去掉参数，保留静态方法签名。未知码、活动停用/未开始/售罄/限领/幂等冲突等 CODE 领取拒绝统一为400“兑换码无效或当前不可兑换，请检查兑换码及活动规则”，不提供可枚举的活动详情；普通id-only领取探测隐藏CODE活动时，与不存在的活动返回相同错误。正常成功仍返回true，会员可在“我的优惠券”查看权益。

## 历史兼容与上线过渡

旧4–32字符码及其摘要保持原值、原活动规则；`codeHash()` 的短码格式仅用于历史读取兼容，不能作为新码安全性验证。短于32字符的输入无论是否匹配活动，都在查询前受额外日额度限制，不能通过换key、填充字符或换活动绕过：填充后的字符串不再匹配原码。长度为32的历史弱码也受通用会员/IP限制，但不能凭长度认定随机性。

不擅自重新生成、公开、删除或失效旧码。运营应授权检查所有历史手工活动，停止旧活动的新领取、改用新建的随机码活动；已有权益快照不变。不要打印旧码进行排查。历史公共码的剩余风险不能被限流完全消除，公开分享的公共码也不是一次性凭据。

## 验收

新增真实 Redis 两独立客户端测试，包括不同错误码20并发×20轮、不断换requestKey20并发×20轮、32位可预测错误码20并发×20轮；另测20会员共享网络、小时额度、IP总额度、短码日额度及TTL恢复。每轮只有固定额度进入领取服务，其余429。

普通测试覆盖Redis故障fail-closed/无请求或异常明文日志、无认证拒绝、统一未知活动响应、原AOP参数日志修复、随机生成、短码兼容、手工长弱码拒绝。数据库测试使用生产创建/领取服务，验证随机摘要仅存储及丢失成功响应后的同key幂等，不重发权益。
