# Phase 6A：单商家多门店订单基础

本轮从 `ca16926b36d7080bbf4018bc93471dd93eb93e95` 开始。经营模型是一个商家的多个门店，会员共享；没有新增商户租户、第二份余额或支付系统。支付接入冻结，订单始终以 `paid=0` 创建。小程序付款 API 有明确冻结门禁，结算页只提交订单，提供取消。

## 现状审计与证据

“可用”只指下述已验证路径，不代表完整商业运营能力。

| 领域 | 原始基线结论 | 代码/执行证据与本轮处理 |
|---|---|---|
| StoreShop/门店管理 | 部分实现、有缺陷 | `StoreShopServiceImpl` CRUD 存在，但保存时按时间重算 status，覆盖暂停营业；管理员只能绑定一个店。现在保存明确 0/1 开关，允许多店授权；下单再检查营业时间。 |

| 分类 | 部分实现 | 分类有 shop_id、启用状态、两级结构。原下单不验证分类；现在验证本店启用的完整父链，循环/跨店/失效拒绝。后台分类不可跨店移动、有商品不得删除。完整分类经营留到 6B。 |

| 购物车 | 部分实现 | 本机存储，无服务端跨设备购物车；原来保留旧价和失效 SKU。现在根据当前门店目录重建合法行/价格/数量，旧无门店关联行直接丢弃。网络失败保留提交标识与购物车供安全重试。 |
| 创建订单 | 存在缺陷 | 原商品快照 `saveCartInfo` 使用 @Async，不在建单事务。新路径同步持久快照、预占记录、订单、提交标识和优惠券绑定。`OrderingDatabaseTest` 真实 MySQL/H2 证实回滚与并发。 |

## 默认业务规则

- 营业开关必须为 1，且处于 Asia/Shanghai 每日营业时间。起止相同按全天营业；跨午夜时间支持。下单锁店铺行，暂停与下单有明确数据库先后顺序。
- 普通订单只支持自取/外卖；未完成的堂食与零元订单明确拒绝，不自动走余额支付。每单至多 100 行，每行整数 1–999；同商品/SKU 重复行拒绝。
- 商品不能跨店移动；SKU 按商品+规格文本定位，客户端金额无效。服务端保存同步名称、规格、单价、数量快照及具体库存行 ID。
- 同会员 `idempotencyKey` 绑定规范化请求哈希；同 key/同内容返回同一订单，冲突拒绝。客户端在失败后保留 key，成功或切店后清理。已取消订单重放旧 key 仍返回原单，新购物需新 key。
- 锁顺序：提交标识 → 门店 → 按 ID 排序商品 → 分类 → SKU → 优惠券；取消是订单 → 按 ID 排序商品/SKU → 优惠券。创建不会再锁一个已有订单；不以 Redis 锁保证正确性。锁超时/数据库异常事务回滚并拒绝，不跳过库存。单店创建使用店铺行串行化，优先正确性，吞吐优化留到测量后。
- 新订单 30 分钟未付款自动取消；数据库扫描默认每 60 秒，单批 100。支持多实例竞争，订单行锁与预占释放标记保证一次性。失败输出订单 ID/异常类别，不输出请求/用户/凭据，保留状态待下次重试。
- 优惠券 `shop_id=0` 通用，CSV 为明确门店；必须属于会员、有效期内、满足商品小计门槛和享用方式。状态是 AVAILABLE/RESERVED/USED/EXPIRED 的派生展示；保留既有 0/1 字段兼容支付。只有精确绑定的新订单取消才返还，不猜测历史 status=1 的原因。
- 会员身份共享；积分/券跨店规则后续配置化，本轮不迁移余额、积分或账本。
- 门店 CSV admin_id 复用已有机制，支持普通店员/店长单店或多店。总部必须有现有 `super_admin` 或明确 `business_headquarters` 角色；角色仍通过既有权限管理授予，迁移不自动给权限。客户端 shopId 与旧 token shopId 都不是授权证据。

## Migration 与兼容/回滚

执行独立 `yshop-drink-boot3/sql/migrations/2026-10-08-multistore-ordering.sql`。先保持支付关闭、暂停新下单并备份；确认既有 5B–5F schema，执行 additive DDL，验证表/列，再统一升级各实例。MySQL 8/InnoDB 验收从原始 seed 的空表 DDL 建隔离库，迁移重复执行并保留原有测试订单。

新增两张非金融表：`yshop_order_submission`（会员+key 唯一，订单引用唯一）；`yshop_order_inventory_reservation`（订单+行号唯一，商品/SKU/数量/released_at）。订单增加 `ordering_version DEFAULT 0`，新单显式为 1；CouponUser 增加可空 reserved_order_id。增加超时扫描和商品预占查询索引。无历史数据回填、默认门店补写或金融记录更新。

回滚时先停止新订单入口，使用新版取消/超时处理全部 version=1 未付订单并确认预占无遗漏，再回退应用；优先保留 additive schema。不要在仍有预占时回旧版取消逻辑，也不要删提交标识重试、直接改 paid 或批量返库存。若已存在已付新版订单，须先人工评估快照/退款兼容，不能自动降级。DDL 回滚并非常规启动步骤，不提供破坏历史记录的一键删表脚本。

## 可复现验收

使用 JDK17、已有 Maven 缓存；先全 reactor install，再运行：

```sh
mvn -pl yshop-module-mall/yshop-module-order-biz test -Dtest=OrderingDatabaseTest -Dsurefire.failIfNoSpecifiedTests=false
python3 tests/business/mysql-acceptance.py
node --test tests/business/cart-context-test.mjs
```

普通集成与 MySQL 使用完全相同的服务和 A/B 两店测试；MySQL 使用源 seed DDL 与正式 migration，随机独立库/账号，finally 清理，不使用开发余额。真实 MySQL 还验证迁移重跑、行锁超时、驱动时间/BIT/tinyint 类型兼容。保留全部既有 payment/wallet/attempt/V3/credential 测试；详细最终数字在交付报告，不能用构建跳过测试代替回归。

小程序自动验收脚本 `tests/business/mini-program.cjs` 使用已登录开发者工具、当前用户的本地未付订单；只创建及取消，原价/库存通过服务端读取，paymentRequests 必须为 0。支付关闭且无真实商户凭据。并发/下架/停业/券异常数据仅在隔离库测试，不修改开发目录商品来演示。
