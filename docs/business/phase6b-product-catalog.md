## 设计决定

- 保留门店独立商品及库存型 SKU；定制/加料配置绑定单个商品，以有界、服务端验证的结构化配置保存，后台使用表单。冷热、甜度、冰量均由商家定义，不硬编码。加料为明确非库存管理。
- 条件组只依赖排序在前的组和选项，防止循环；不适用组不得提交。必选/单选/多选/重复数量及非负两位小数差价由服务端校验。
- 商品配置版本参与下单与客户端确认；SKU 价格和配置从商品锁后的最新记录读取。版本不符拒绝并要求刷新确认；合法重放仍按旧 submission 返回原订单。
- SKU ID 不重建；历史 SKU 停售保留。已有 SKU 库存走独立增减调整，按商品 → SKU 加锁，记录前后值/操作者/原因；总库存为全部 SKU 可用库存之和，停售库存也计入物理汇总。
- 商品编辑允许名称、价格、配置等安全修改；规格结构变更保留旧 SKU ID、库存、预占引用并停售旧组合；新增组合生成独立 SKU。禁止物理删除仍被预占的商品/SKU。历史快照不依赖当前商品反算。
- 批量操作全有或全无；跨店复制验证两店授权、目标分类，生成独立 SKU 和配置，默认下架/零库存，复制 key 幂等，禁止覆盖目标商品。
- 支付与 reconciliation 始终关闭，不改余额、积分、账本或 PaymentAttempt。这里只创建 paid=0 订单。

实施、迁移和最终验证记录在本文件及 `phase6b-verification.md` 持续补充。

## 数据模型、价格与兼容边界

`catalog_version` 从 0 开始，存量商品无定制配置可继续接受原请求。首次商品维护/配置/改价/规格停售后递增版本，新客户端提交每条商品的 `choices={version,selections}`，服务端不接受选项价格。版本更新后的商品必须重新确认，不能用旧客户端静默接受变价。配置附属于具体门店商品，复制后为独立记录；共享会员、优惠券规则、余额和积分沿用 Phase 6A。

库存型 SKU 对应现有 `AttrValue` 的 ID、组合字符串、独立价格和可售库存。定制 `CUSTOM` 与加料 `TOPPING` 都不消耗独立原料库存；可配置名称、启用、单/多选、最少/最多总份数、同项最多份数、默认数量与前置选择条件。不是对饮品全局硬编码冷热甜度。配置上限：20 组、每组 30 值、SKU 100、选择 100、配置 JSON 64k；条件只能指向前面的组，拒绝循环或未知选项。数量必须整数，差价非负且精确到分。

每行金额为 `(服务端 SKU 基价 + Σ合法选项每份差价 × 份数) × 商品数量`；整单沿用服务端配送和优惠券校验，客户端预览不成为成交证据。服务器使用 BigDecimal，客户端预览使用整数分。重复同选项输入拒绝；同 SKU 的不同定制允许多行，库存按其数量分别预占。请求幂等哈希包含规范排序后的选择，重放不重新计价或再次扣库存。

`cart_info` 记录 version=1 的成交快照：商品 ID/名称/门店、SKU ID/组合、catalogVersion、basePrice、每个选项的组名/名称/类型/单价/数量、extra、unitPrice、商品数量、lineTotal。后续名称/价格/配置/停售不能修改这些快照。旧快照不回填，详情页面兼容旧格式。原订单取消、库存 reservation 与 PaymentAttempt 防护完整保留。

## 库存、权限和事务

商品编辑中的已有 SKU 库存只展示；服务端不信任编辑表单的库存、销量或配置覆盖。相同规范组合复用旧 ID/unique，退休组合保留并停售。新增 SKU 的初始库存和改价记录商品操作审计。可售库存增减调整提供 expectedStock、delta、reason、idempotency key；商品 → 操作记录 → SKU 锁保证与下单互斥，expected 不符要求刷新。条件更新、汇总和审计插入同一事务，失败全回滚。

后台总库存 = 全部 SKU 的当前可售库存之和，包含停售但尚有实物的历史 SKU；顾客目录摘要只计启用 SKU 的可售库存/最低售价。预占已经从可售量扣除；取消按原 reservation 返回原 SKU，一次且仅一次。停售与库存为零是不同操作，不会清除预占或历史销量。

维护分类/创建编辑/复制/批量操作按门店 ID 有序锁门店，再锁商品、分类链及 SKU；普通改价/调整/定制由商品锁串行化。订单沿用原订单/门店/商品锁次序，所有经营路径不反向锁订单、PaymentAttempt 或金融账本。所有后台操作叠加既有功能权限与 StoreAccess 资源权限，逐个检查批量商品、复制双方门店和目标分类。总部仅复用已有明确总部角色，未新增超级权限，普通店员无 product:update 时不能定价/调库存。

批量上/下架和分类最大 100 个唯一商品，全成功或全回滚；跨门店复制使用 actor+key 幂等，payload 不一致拒绝，默认下架/零库存，新 product/SKU/unique，不覆盖目标价。调整库存、售价、复制的审计表为 `yshop_product_operation`，不是金融账本；没有删除/修改审计入口，查询最近 200 条。

## 后台及顾客操作

后台选择门店 → 分类创建（图片、排序、两级、启停）→ 新建饮品/图片/介绍/库存杯型 → 经营设置配置定制和加料 → 单 SKU 调价/调整库存/停售 → 查看操作者与原因 → 批量经营或复制。表单不要求商家编辑 JSON；已有商品门店不允许在编辑中变更，分类加载只在对应门店内。规格模板由总部维护，仍可复用。

小程序从实际启用 SKU 选择，不推测不存在的笛卡尔组合；条件不适用即移除选择，必选漏选不能提交。购物车身份含 SKU+选择，跨店/配置变更清理无效项，数量按同 SKU 所有行合并检查库存。网络失败保留下单 key，过期配置提示刷新，后台仍逐条拒绝伪造/已下架/售罄输入。支付保持冻结，仅创建待付款订单及正常取消。
