# 打印机管理：实现与交付说明

本次从 `develop` 的 `ca16926` 创建 `feature/printer-management`，恢复总部后台的打印机管理。第一版只注册易联云云端适配器，支持设备维护、启停、设备连接/取消授权、门店绑定、状态查询和测试小票，不接入订单打印。

## 404 的原因及修复

首页原来跳转 `/shop/web-print`，历史菜单却挂在 `/mall` 下；菜单 2308 和其按钮权限被软删除，且 `store/webPrint/index` 对应的页面不存在。后端也没有配套管理接口和设备表。

新页面为 `mall/store/printer/index`，正式地址 `/mall/web-print`。迁移恢复菜单 2308 和原有查询、新增、修改、删除权限，增加授权、门店绑定、测试权限。旧 `/shop/web-print` 仅在总部账号有查询权限、且新菜单已加载时重定向。首页入口和动态菜单对门店账号隐藏；后端每项操作仍检查独立权限和总部身份。

## 扩展方式

调用链为 `PrinterController → PrinterService → PrinterProviderRegistry → PrinterProvider.openSession() → PrinterSession`。页面和业务服务只消费通用厂商说明、连接类型、配置字段和能力，易联云签名、访问令牌、协议字段及打印指令封装在 `yilianyun` 包中。

新增厂商实现 `PrinterProvider` 并注册为 Spring Bean，提供稳定的 `code`、配置字段和能力。状态映射成 `ONLINE / OFFLINE / PAPER_OUT / UNKNOWN`；打印接收通用 `Receipt`，适配器负责转换指令并返回服务打印编号。非云端连接也通过厂商提供的 `connectionTypes` 表达，不需要修改管理页面。未实现的能力声明为 false；业务层同样拒绝不支持的操作。

`openSession()` 在设备事务之外准备凭证；返回的会话不得重新访问令牌数据库或申请嵌套数据库连接。调用入口和令牌存储均拒绝在活动业务事务内准备会话。设备事务内只使用已准备的会话执行受超时限制的厂商操作；操作意图过期后不得再发送。令牌仍独立提交、加密持久化并按应用账号串行获取。

厂商说明新增 `requiresAuthorization`，与授权操作能力分开；易联云为 true，无需授权的 USB/局域网适配器为 false。前端缺失该字段时保守按 true 处理。无需授权设备显示“无需授权”，无需进入 `AUTHORIZED` 即可测试打印，但仍检查启用、厂商配置及打印能力。模拟 USB 和局域网适配器已覆盖保存、绑定、状态、打印和删除。

当前支持易联云自有型应用。第二个模拟厂商已通过相同业务服务完成保存、授权、绑定及测试打印，生产环境只注册易联云实现。

## 数据与状态约束

新增 `yshop_printer`、`yshop_printer_binding`、`yshop_printer_test_job`、`yshop_printer_provider_token` 四张表。设备按已验证登录身份的租户编号读写；存在租户上下文时要求编号一致。关闭多租户时，登录缓存中的空租户与数据库默认值 0 统一使用单租户范围 0；开启多租户时仍拒绝缺失的身份或上下文。现有门店表本身是共享表，没有租户列，本次沿用原有总部门店范围。

同一门店可绑定多台打印机，每台打印机只能属于一个门店。`provider_code + device_code` 全库唯一，包括软删除设备，防止同一物理设备被多个租户重复使用；同一租户重新添加已删除设备时恢复原记录。设备身份不能编辑。删除前必须解绑门店、确认取消授权；门店删除在同一事务中清理其打印机绑定，失败时整体回滚。

设备配置和应用访问令牌使用 AES-256-GCM 加密，包含随机 nonce 和上下文认证。详情只返回已配置的字段名，编辑留空保留原值；授权状态不明确时禁止更换密钥或删除。配置写入不记录请求内容，公共日志清洗也覆盖设备密钥和加密配置；外部原始响应不会进入错误或日志。

授权意图先落库再调用厂商，异常中断保留 `UNKNOWN`。设备操作标记不会因时间经过自动释放；需要总部授权人员先确认原发送方已停止、厂商/设备侧操作已经结算，再通过 `GET /store/printer/operation/pending?id=...` 查看令牌，并以 `POST /store/printer/operation/resolve` 提交该令牌、原因和两项确认。恢复事务会写操作者审计、将对应授权/状态/测试任务保留为 `UNKNOWN`，再按精确令牌清标记；不会重发厂商请求。重连时先尝试查询已有设备状态，避免盲目重复注册。取消易联云授权调用官方解绑接口，对于自有型应用会解除开发者账号和设备的绑定。

已连接或授权待确认的设备可显式“重新连接”：使用现有授权权限，确认后真实核验云端状态，必要时只尝试一次重新注册，不根据本地缓存提前返回成功。重新连接保留门店绑定，失败保持 `UNKNOWN` 并返回原因；取消授权仍需先解绑。

测试请求先记录 `SUBMITTING`，再调用厂商。客户端同一次未确认请求复用编号，服务端唯一约束与设备锁保证重复请求不重复发送；易联云同时传入稳定 `origin_id` 和 `idempotence=1`。超时、响应异常或进程中断会标为 `UNKNOWN`，不会自动重试。长时间未结束的任务展示为待确认，管理员确认实体设备后才可主动发起新测试。“已提交”只代表云端接受请求，不代表设备实际出纸。

所有 GET 设备查询保持只读。`GET /store/printer/status` 仅返回缓存状态、时间和错误，不准备厂商会话、不刷新令牌、不写数据库；页面的“刷新状态”显式调用 `POST /store/printer/status/refresh`，仍要求查询权限。

待确认请求使用 `GET /store/printer/test-print/get?id=...&requestId=...`，查询权限即可读取，返回记录或 null，既不创建任务也不触发打印。未找到记录时保留编号，用户需另行确认“发送此测试请求”，继续复用同一编号。设备或厂商停用后，已有编号的查询仍可使用。网络异常保留编号，只有明确结果或设备确认流程才清理。

设备列表的 `deleted` 参数默认 false，true 查询已删除设备；详情包含 `deleted` 标记。历史设备只提供记录查看，同一租户可查询历史设备的分页记录及单次结果；所有变更操作仍拒绝已删除设备。列表及记录窗口仅接受当前查询的最新响应，关闭或切换设备、筛选、分页时旧响应不能覆盖新结果或加载状态。

订单打印在厂商会话准备完成后重新校验订单租约、设备门店、启用、授权与在线状态，再事务性写入 `yshop_order_print_device_claim`，随后才执行厂商 I/O。发送期间解绑、换绑、禁用、取消授权与删除会返回 `PRINTER_BUSY`；会话准备期间若设备已换店，旧门店任务失败为 `PRINTER_NOT_BOUND`，不会向新门店发送。云端接受状态仍不表示实际出纸。

若进程在厂商调用期间退出，打印任务会成为 `UNKNOWN`，设备占用不会随租约过期自动释放，后续发送与设备变更均保持阻止。总部授权人员只有在确认原发送进程已停止、并从打印服务或设备核实未出纸后，才能在订单打印页执行“核验后释放占用”；系统会记录操作者、原因、原错误和幂等请求编号，并将原任务置为 `FAILED/OPERATOR_CONFIRMED_NOT_PRINTED`。如需补打，再通过原任务创建关联重打子任务。结果不明时不得释放或重打；不得直接删除占用记录或自动重发。

HTTP 连接超时 3 秒，单次请求（含响应体）最多 10 秒，响应体最多 64 KiB，不跟随重定向。设备名称、门店名称中的标签及旧版打印指令符号会被转换成普通文本。

## 部署顺序

1. 备份数据库，依次执行 `yshop-drink-boot3/sql/migrations/2026-10-05-printer-management.sql` 与 `2026-10-22-printer-operation-recovery.sql`。脚本适用于原始 MySQL 8/InnoDB 表结构，可以重复执行；不迁移旧 `uniprint_id`。
2. 部署新后端与前端。SQL 绕过菜单服务缓存，需通过现有缓存管理清理 `permission_menu_ids` 中 `store:web-print:*` 对应的缓存项。不要清空整个 Redis 数据库。
3. 给需要使用功能的总部角色分配菜单及按钮权限。超级管理员按现有机制获得所有权限，普通角色不会被自动扩权。新版首次加载会自动重新获取旧版缓存的用户权限和菜单；已打开的页面需刷新。之后修改角色权限时仍按原有流程重新登录。
4. 暂无账号时保持打印服务关闭。可先维护设备与门店绑定，不填写终端密钥；数据库迁移仍需完成。
5. 获取易联云自有型应用及实体小票打印机后，在部署环境配置以下变量，再重启后端。变量值来自部署环境的秘密配置，不能提交到仓库。

### 自提履约与订单打印迁移（2026-10-22）

自提履约与订单打印使用独立增量迁移，必须先备份并在 MySQL 8/InnoDB 隔离库验证，再部署依赖这些表的后端。按顺序执行 `yshop-drink-boot3/sql/migrations/2026-10-22-order-fulfillment.sql`、`2026-10-22-order-print-event.sql`、`2026-10-22-order-print-job.sql` 和 `2026-10-22-order-print-device-claim.sql`。最后一项创建订单发送中的设备持久占用记录及人工核验释放审计表；旧版本不会创建它，漏执行时新订单打印及崩溃恢复不可用。执行后核对履约列、打印任务/事件/占用/释放审计表、索引、外键均符合迁移定义，再部署应用。

这些脚本只增加履约状态/日志和持久打印意图，不回填历史履约状态，不重发旧订单，也不接触支付、余额或积分数据。不要用 `CREATE TABLE IF NOT EXISTS` 成功就推断已有表结构兼容；若目标库存在同名对象，先对照 DDL 核验。真实厂商调用与真实出纸仍需单独授权和验收。

| 变量 | 用途 |
| --- | --- |
| `YSHOP_PRINTER_ENABLED` | `true` 开启易联云接口，默认 `false` |
| `YILIAN_YUN_CLIENT_ID` | 易联云自有型应用 ID |
| `YILIAN_YUN_CLIENT_SECRET` | 易联云应用密钥 |
| `YSHOP_PRINTER_ENCRYPTION_KEY` | 独立的 32 字节随机密钥，Base64 编码 |

加密密钥必须持久保存并备份，不能在每次启动时重新生成，也不能直接替换已有密钥；替换需要迁移已加密的数据。设备终端号、终端密钥通过后台表单录入，密钥只写不读。

访问令牌按应用账号加锁获取并加密持久化，重启复用。采用官方自有型应用的长期令牌，不在每次请求时重新获取，避免消耗每日额度。若应用外部操作使令牌失效，先停止相关调用，由运维确认原因后清理对应 `yshop_printer_provider_token` 缓存记录，再显式重试；不要自动循环获取令牌。

回滚时关闭打印服务，并将菜单 2308 的 `status` 设为 1、清理对应权限缓存及重新登录；恢复旧版本应用。保留新增表、凭证密钥及测试记录，不执行删表回滚。新版本门店删除依赖绑定表，必须先完成迁移再部署。

## 本次集成的迁移与删除合同（2026-10-20）

门店删除先执行真实 `StoreAccessService.requireHeadquarters()`，再持有门店行锁；打印绑定也先锁门店。同一事务中检查门店逻辑删除影响行数为 1，再锁定原绑定并检查清理影响行数。删除失败、清理失败或行数异常均回滚。并发绑定要么先完成后被删除清理，要么在门店删除后明确拒绝。

生产迁移首先校验旧门店与菜单表的必需列、类型、默认值、主键、InnoDB 和触发器，父菜单 2000、历史页面 2308、按钮 2309–2313 及新增权限的唯一身份。四张基础打印表必须全部不存在或全部完整存在；完整结构要求原 38 列、20 个索引列、13 个约束的精确合同，并核对大小写敏感身份排序、外键目标及非级联规则、已强制执行的 CHECK 表达式、InnoDB、表排序和无触发器。操作恢复迁移兼容上述历史 38 列结构并加入两个恢复元数据列，最终为 40 列；只出现一个恢复元数据列或审计表结构不完整时拒绝迁移。部分结构或冲突在菜单写入前拒绝，保留所有业务表结构及行。迁移临时预检过程在成功后删除；失败时保留过程，不执行业务修复。

H2 明确排除 MySQL `information_schema` 预检，只承担服务、事务及权限测试。真实 MySQL 专项使用 `mysql:8.0` 的 owned 一次性容器、动态回环端口、独立合成库与账号和 UTC 时钟；不读取开发数据库。精确清单、SHA/内容摘要、runId、Surefire 产物摘要、源码未变与 owner 清理均通过后才写最终 PASS。首次迁移和完整重复迁移须保留旧门店内容与角色菜单分配；负向迁移比较全部业务 DDL/行/触发器快照，不自动补表、补约束、移动冲突权限或追加角色授权。

本次真实执行收据在工作树 ignored 的 `.quality/printer/` 与 `.superpowers/sdd/2026-10-19-next-stage/task-5-report.md`，不复用下文旧计数。打印服务默认仍为关闭，`ACCEPTED` 仅表示云端接受；真实厂商账号、实体设备、出纸与订单自动打印不在本轮范围。
