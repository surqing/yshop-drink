# D001 身份入口修复：审查与运行说明

本分支基于 PR #16 的 31cd487，仅处理 D001 剩余身份入口和已复现的关联会员写入问题。D004 已有修复保持；积分兑换库存、数量缺陷不在本阶段。草稿 PR 不代表生产发布许可。

## 业务契约

- 短信、密码登录保留原有接口。手机号支持国内号码及 +86/0086 前缀，内部统一为11位号码。请求 openid/from/socialCode 不决定短信或密码登录的会员，也不绑定其他会员。
- 小程序手机号登录使用 `/member/auth/weixin-mini-app-login`，同时提交新鲜 phoneCode 和 loginCode；客户端已适配。旧 encryptedData/iv 路由已移除，缓存 openid 不能作为登录凭据。失败的手机号授权必须重新授权，不能自动重放。
- auth-session 每次用配置中的 SDK 换取新鲜身份；未绑定身份可以返回 openId，但没有会员令牌。微信公众号同样使用实际 SDK 验证结果。
- 同一手机号和同一平台身份的现存归属必须为同一 UID；不同 UID 冲突拒绝，不合并会员或移动资产。可信的单边身份可以补全到原 UID。
- MEMBER 绑定/解绑使用当前令牌 UID、该会员当前手机号的独立短信场景5/6和新鲜平台证明。解绑只清除准确匹配的当前身份。普通资料、后台普通编辑及陈旧整对象更新不能写身份字段；后台资产使用调整入口。
- 手机号变更验证数据库当前旧手机号及旧、新号码证明；成功修改/绑定/解绑撤销会员令牌族。数据库失败时证明、身份、SQL令牌一起回滚；缓存变更在提交后执行。
- 收货锁定当前本人订单，再锁会员；重读付款/退款/系统删除/状态，条件状态更新必须恰好1行。状态记录、积分、真实流水同一事务。保留已付款状态0/1/2的原有收货资格，不新增履约政策。后台调整先锁会员，积分只做精确字段写入，扣减至0时流水记实际扣减量。

## 数据库与上线前置条件（本任务不执行生产步骤）

现有 yshop_user 增加 mobile/openid/routine_openid 三个完整唯一索引，包含逻辑删除会员；空身份使用 NULL，平台ID采用 ascii_bin。应用启动检查必要索引、列定义及身份命名空间。没有新增身份表。

执行 SQL 前必须冻结全部身份写入、建立并验证数据与表结构快照，核实实际小程序/公众号 AppID 与租户设置。若存在 system_social_client，需按实际受信 AppID设置脚本会话变量 @member_mini_appid/@member_mp_appid，并核实所有启用 MEMBER 配置；不能使用示例 AppID作为事实。

脚本预检规范化后的重复手机号、两类重复 openid（包括删除行）、非法非空身份、非零租户、残留 MEMBER 通用社交绑定、部分索引及 AppID偏差。冲突时在数据更新前失败，由维护者逐条核实证据；不得批量删除、合并或改变 UID、订单、余额、积分。缺乏可信历史身份来源时不得根据昵称、缓存或旧请求猜测归属。

“没有历史会员/旧客户端”仍需运维核实。未核实不得上线此强制启动检查或移除旧接口的版本。存在历史冲突时，本阶段脚本会阻止切换；隔离冲突、正常会员连续登录及安全账号恢复的完整迁移系统不在本分支，不能将其称为已实现。手机号和微信证明均丢失时也没有自动恢复后门，须由人工可信核验流程处理。

MySQL DDL隐式提交；应用事务不能回滚整段迁移。UPDATE 后 ALTER 失败必须继续冻结写入，按已验证快照和原始列定义恢复身份字段/表结构，核对 UID及订单/资产不变。禁止在有新写入后覆盖快照。57项真实数据库验收含前向迁移、冲突拒绝和自有合成快照还原验证；生产规模及历史数据从未执行。

## 回归与证据

统一入口：QUICK、JAVA、BUILD、FRONTEND、INTEGRATION、CROSS-END、BROWSER、MUTATION、PERFORMANCE。INTEGRATION中新增独立自有 MySQL/Redis会员接受测试，实际服务/事务/SQL/令牌缓存保持真实，外部微信/短信发送使用合成边界。原始 D001–D009 HTTP/浏览器断言另行运行并保留失败状态。

会员接受测试必须通过 `tests/quality/member-score-mysql.py --output <仓库外私有新目录>`；启动器从当前工作树 reactor编译依赖，按精确用例名/数量/运行ID/源码摘要验证，不采用旧安装产物。57项包含20×20短信身份请求，以及不存在账号、错误密码、禁用账号的真实失败审计落库与合法密码登录对照；双JVM验证/刷新/注销负载独立由PERFORMANCE运行，报告吞吐、P95/P99及锁等待。15秒P99仅为冒烟预算，不是生产容量或SLO。

密码认证的失败审计仅在认证事务回滚完成后，以独立事务持久化原始会员编号、账号和拒绝结果；客户端原有错误码保持不变。成功审计、Token SQL和登录元数据仍在同一事务提交，缓存仅在提交后发布。审计数据库故障仍拒绝登录，不将审计失败转为认证成功；本阶段不引入异步审计队列。

MUTATION仅修改临时源代码副本，报告原始基线、完整副本摘要及变异片段摘要。断言失败才算捕获变异，编译、初始化、SQL环境错误不算。原始及最终失败证据保存在仓库外，不提交凭据、原始运行日志或截图。

## 回滚与阶段门槛

每阶段独立分支/提交/草稿PR。当前阶段需身份与D004目标通过、共享钱包/支付回归通过、全部规定范围真实执行、独立最终审查及新PR最终CI确认。其他已知失败必须逐项保留，不自动开放质量门禁或 Phase6D。

应用回滚不得重新开放不可信 openid 登录、普通资料写身份或重复奖励路径。若需退回旧版本，先停用受影响入口，并维持必要唯一性/权限约束。数据库回滚仅在写入冻结且快照可验证时由维护者执行；不自动修复或补偿真实积分、订单、资金。

完成 D001 并提供实际证据后停止，等待用户确认再开始 D003，随后再进入 D002。真实微信、真实短信发送和生产恢复/迁移没有执行，必须单独由维护者验收。
